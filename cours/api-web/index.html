Une seule porte.
Toutes les applis.

Une web, c'est la porte d'entrée d'une application : l'appli iPhone, l'appli Android et le site lui envoient leurs demandes par internet. Ce cours t'apprend à lire ses réponses, puis à en écrire une.

Les mots soulignés en pointillés s'expliquent : clique dessus.

Chaque appli se branche sur la même porte : elle envoie des requêtes HTTP, et le serveur répond à toutes de la même façon.

À quoi sert ce module

Sans API, chaque appli fouillerait la base.

Instagram existe sur iPhone, sur Android et sur le web, et les trois affichent les mêmes posts. Si chaque appli allait chercher elle-même dans la , il faudrait lui donner la clé de toutes les données, et changer la base casserait trois applis d'un coup. Avec une API, un seul garde les données et répond à tout le monde.

Changer une appli sans casser les autres

Chaque appli parle seulement à la porte. On peut en refaire une, ou en ajouter une, sans toucher au serveur.

Savoir tout de suite si ça a marché

Chaque réponse commence par un code de statut : 2xx ça a marché, 4xx la demande pose problème, 5xx le serveur a un problème.

Une langue que tout le monde parle

HTTP pour les demandes, JSON pour les données : Java, Swift, JavaScript, tous les langages les comprennent.

    Fiche · API web (REST)

    Le cours sur un écran, à relire la veille.

    À quoi il sert

    • Une API web est la porte d'entrée d'une application : d'autres programmes lui envoient des requêtes HTTP et reçoivent des réponses.
    • Plusieurs applis (iPhone, Android, site) partagent les mêmes données sans toucher à la base.

    Les notions, dans l'ordre

    1. Client et serveur : requête et réponse
    2. HTTP : méthode et URL
    3. Codes de statut (2xx, 4xx, 5xx)
    4. JSON : objets et listes
    5. API web (REST) : tout assembler

    Les trois pièges

    • Croire que toute erreur vient du serveur : un 4xx dit que c'est la demande.
    • Confondre récupérer et afficher : GET récupère les données, c'est l'appli qui les affiche.
    • Oublier de nommer ce qu'on vise dans l'URL : /posts/42/comments/7, pas /posts/42/7.
